# Status

**2026-11-07.** The repository is a working PC-tethered agent plus a signed,
installed HarmonyOS app. The Python harness captures an observation, asks a
model for one action, classifies it, executes it, re-observes, verifies and
appends a hash-chained record. It has 188 agent tests (277 across the harness)
and a validated 20-task bench format. The ArkTS `apps/harmony/core` has a screen-aware
payment gate and a loop that captures observations. The HAP builds with DevEco
6.1.1 / API 24, the Local Tests pass, and the HAP is signed with the SDK's local
OpenHarmony debug kit and installed on the Pura 90 emulator (`bm install` ok,
`EntryAbility` starts, first frame drawn, six tabs render).

Device control now has two backends:

- **on-device accessibility** — extension declared, ACL granted, framework lists
  it; this emulator has no Settings page to enable it, so capture/tap stay off;
- **PC bridge** — `pc-agent bridge` over HTTP, token-authenticated, wired into
  the app and verified end to end (observe -> model -> tap -> re-observe). This
  is the path that works on this emulator.

The standalone claim is still **not** met; the toolchain, tethered, install,
UI-wiring and app-control-over-bridge claims are. Parity with Mika is
**12.5 / 15 (83%)** with the PC attached; see `docs/product/parity.md` for the
per-row breakdown.

## Screens (2026-11-07)

The app now has a **left drawer**, like Mika's root screen. It lists Chat, Plans,
Memory, Browser, Screens, Settings, About and More, then a Tools group: Apps,
Runs and batches, Models, Usage, Phone setup, Self-check and Welcome.

- **Conversations** live in the drawer: every chat is saved, `+ New chat`
  starts a fresh one, and selecting an older chat restores it. The current chat
  also survives a restart.
- **Welcome** is shown automatically on the first launch and once only.
- **Settings** has the Mika-style sub-pages: App access, Computer access,
  Self-check, Developer and About.
- **Runs** opens a per-run timeline (started, finished, duration, approval,
  payment, detail).
- **Screens** renders a live JPEG from `pc-agent bridge /screenshot` and polls
  every 3 s while the page is open (Live toggle); verified on the emulator
  (1.2 s per frame). The bridge URL and token are saved so the connection
  survives a restart.
- **More** adds Source (provider, endpoint, control backend), MCP servers (what
  runs on the PC), Files (export and inspect the JSON) and License.

What is still narrower than Mika: Source is a summary, not a citation list;
there is no MCP server on the phone, only the PC side; Files shows the export as
text rather than a document viewer; and the run history is a list that opens
one timeline at a time.

## What works now

```bash
hopa-agent observe --json
hopa-agent run "..." --steps steps.json
hopa-agent records --path .hopa/runs.jsonl
hopa-agent verify-chain --path .hopa/runs.jsonl

cd apps/harmony
hvigorw assembleHap --no-daemon
hvigorw test -p module=core@default --no-daemon -p coverage=false
```

Sign and install with the SDK's local OpenHarmony debug kit (no Huawei account):

```powershell
.\tools\scripts\build.ps1
.\tools\scripts\sign-app.ps1 -Install
```

`tools/signing/` is gitignored; `tools/scripts/sign-app.ps1` regenerates the app key, the
certificate chain, the debug profile (with the connected device's UDID) and the
signed HAP on any machine that has the SDK.

## Honest limits

- There is no background screen and no hidden virtual display.
- The HAP contains no Python runtime.
- The phone app cannot control other apps until the accessibility service can be enabled (the emulator image has no such page).
- ArkWeb rendered black after one app restart on the emulator; the DOM text and `runJavaScript` still worked, so the page-text path is proven but rendering is not reliable on this image.
- Numbers in this repository are local until a device run says otherwise.
