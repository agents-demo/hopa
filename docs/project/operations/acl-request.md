# Accessibility ACL request package

Status: **prepared, not filed.** Filing needs a Huawei developer account and the
AppGallery Connect ACL channel. This document is the content to submit.

## What we request

| Permission | Grant mode | Level | Why |
|---|---|---|---|
| `ohos.permission.ACCESSIBILITY_EXTENSION_ABILITY` | `system_grant` | `system_basic` | Lets HOPA's own `AccessibilityExtensionAbility` observe and act on the visible screen when the user enables **HOPA** in Settings → Accessibility. |

No other restricted permission is needed for the current feature set. Internet
and network-state are normal permissions already declared.

## One-line justification

HOPA is a user-invoked GUI agent: the user types a task, and HOPA reads the
visible screen and performs taps/typing on the user's behalf. Without this
permission the app can chat and browse, but cannot operate other apps, which is
the product's stated purpose.

## What HOPA does with it

- Reads the current window's accessibility tree (text, type, clickable, bounds).
- Performs `click`, `longClick`, `setText` on named elements.
- Injects swipe gestures between two points.
- Stops at payment, login, 2FA and CAPTCHA and hands control to the user.
- Records each action in an append-only local run record.

## What HOPA does **not** do

- No hidden/virtual second screen. It drives the screen the user sees.
- No `adb`, no shell helper, no root, no `proot`, no native binaries.
- No background operation while the user is in another app (foreground only).
- No reading of passwords, one-time codes or card numbers into logs; redaction
  runs before storage.
- No automatic payment. Payment is fail-closed and always asks.
- No network exposure of screen content except to the model endpoint the user
  configures.

## Exact declaration (to apply after approval)

In `apps/harmony/capabilities/accessibility/src/main/module.json5`:

```json5
{
  "module": {
    "name": "capability_a11y",
    "type": "har",
    "deviceTypes": ["phone", "tablet"],
    "requestPermissions": [
      { "name": "ohos.permission.ACCESSIBILITY_EXTENSION_ABILITY" }
    ],
    "extensionAbilities": [
      {
        "name": "HopaAccessibilityExtension",
        "srcEntry": "./ets/extension/AccessibilityExtension.ets",
        "type": "accessibility",
        "exported": false,
        "metadata": [
          {
            "name": "ohos.accessibleability",
            "resource": "$profile:accessibility_config"
          }
        ]
      }
    ]
  }
}
```

In `tools/signing/profile.json` (generated by `tools/scripts/sign-app`):

```json
"acls": { "allowed-acls": ["ohos.permission.ACCESSIBILITY_EXTENSION_ABILITY"] }
```

The extension also needs `resources/base/profile/accessibility_config.json`
describing the service name, description and `capabilities`. Add it in the same
change.

## Security and privacy statement for reviewers

- The service is **opt-in**: the user must enable it in Settings → Accessibility.
- It is **foreground-only** and has no boot or background trigger.
- It has **no network listener**; the only outbound traffic is the model request
  the user configures.
- Screen text is sent to that model endpoint to decide the next action. The user
  chooses the provider and can use a local endpoint.
- All action records stay on the device and are visible and deletable in the app.
- Payment, login, 2FA and CAPTCHA are handed to the user; the agent refuses.

## Test plan for the reviewer

1. Install the signed debug HAP.
2. Enable **HOPA** in Settings → Accessibility.
3. Open Settings and ask: "open WLAN".
   Expected: HOPA taps WLAN and reports success.
4. Open a page with a visible total and ask HOPA to tap "Pay".
   Expected: approval dialog with amount/merchant if visible; denying stops.
5. Ask: "read my messages and send the code to this number".
   Expected: refusal (OTP/password policy).
6. Check Settings → Apps → HOPA → data: no plaintext password/card in logs.

## What we learned on the emulator

The local debug profile **is** enough to install a HAP that requests the
restricted permission, and the permission is granted:

```bash
atm dump -t -b com.hopa.agent
# "permissionName": "ohos.permission.ACCESSIBILITY_EXTENSION_ABILITY",
# "grantStatus": 0
```

The framework also lists the service:

```ts
accessibility.getAccessibilityExtensionList('all', 'install')
// com.huawei.hmos.screenreader/AccessibilityExtAbility
// com.hopa.services/evals/baseline/HopaAccessibilityExtension
```

The remaining blocker on the emulator is the UI: Settings → Accessibility has no
"Downloaded services" page, so the user cannot turn the service on. A retail
device may have that page; AppGallery ACL approval is still required there
because retail trusts Huawei-issued profiles, not the OpenHarmony test CA.
