# Accessibility (a11y)

Status: **code compiled, not active.** The extension is not declared, no ACL has
been filed, and no device test has run.

## What exists

- `A11yBridge` — attaches to `AccessibilityExtensionContext`, captures the
  window root, and converts it into the core `Screen` / `ScreenNode` model.
- `HopaAccessibilityExtension` — `onConnect` / `onDisconnect` attach and detach
  the bridge.
- `A11yCapability` — handles `a11y.observe` by capturing a screen; returns a
  typed failure when unavailable.

What the bridge reads from each node:

| Field | Read |
|---|---|
| text / accessibilityText | yes |
| componentType | yes |
| bounds (rect) | yes |
| clickable | yes |
| checked | yes |
| children | yes |
| id | no (not exposed in `ElementAttributeValues`) |
| enabled | no (defaults to true) |

## What does not work yet

- The extension is **not declared** in `module.json5`.
- No ACL request has been filed.
- `ui.tap`, `ui.type`, `ui.swipe`, `ui.back`, `ui.home` are **not** executed
  through accessibility.
- Capture is pull-based; accessibility events do not trigger it.
- No OCR, vision, throttle, stale-ref invalidation or gesture-conflict policy.
- The API calls are marked deprecated in API 24; they compile, but the API 26
  signatures must be re-checked.

## How to enable it

1. File the accessibility ACL request.
2. After approval, declare the `extensionAbilities` entry of type
   `accessibility` in `app/capabilities/a11y/src/main/module.json5`.
3. Install the signed HAP.
4. Enable **HOPA** in `Settings → Accessibility`.
5. Verify `onConnect` runs and `A11yCapability.isAvailable()` returns true.

Do not claim the capability works before all five steps are verified.
